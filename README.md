# standard4j

以 Java 语言定义的**开发标准库**。这里的"标准"不是语言标准库，而是把业务开发中反复出现的各类标准沉淀为可复用代码：行政代码、国家/民族/性别等字典代码、证件与证照标准、业务异常体系、命名标准（实体字段规范）、脱敏规则接口、平台标准等。

> 当前状态：**设计定稿，编码未开始**。详细设计见 [docs/DESIGN.md](docs/DESIGN.md)。

## 标准清单

| 包 | 内容 | 对齐标准 |
|---|---|---|
| `code` | 统一字典模型（code / name / status / sort / 层级）与查找约定；通用业务字典 | 自定模型，字典项逐一对齐国标 |
| `certificate` | 证照类型：目录代码、证照标识（OID）、发证机构 | **GB/T 36901~36904-2018（电子证照系列）** |
| `exception` | 业务异常体系、统一响应码接口 `ResCode`、错误码规范 | 自定 |
| `entity` | 命名标准：**业务字段与元数据全部以可组合接口（getter/setter）落实**（`Nameable`/`Certifiable`/`Auditable` 等，字段类型绑定字典枚举）；业务单号格式规范 | 字段语义对齐国标 |
| `validate` | 统一校验器接口与内置校验器（公民身份号码、统一社会信用代码、手机号、银行卡号等） | **GB 11643、GB 32100、GB 11714、ITU-T E.164、ISO/IEC 7812** |
| `money` | 不可变金额模型（`BigDecimal` + ISO 4217 货币），禁用浮点表金额 | **ISO 4217** |
| `unit` | 计量单位字典与换算 | **GB 3100/3101/3102** |
| `region` | 国家/地区、行政区划 | **ISO 3166-1**（alpha-2 主键 + alpha-3 + 数字码）、**GB/T 2260**、GB/T 10114 |
| `i18n` | 语言、货币、时区、Locale | **ISO 639-1、ISO 4217**、IANA tzdb |
| `human` | 性别、婚姻状况、政治面貌、民族、学历、健康状况、证件类型、运营商、行业、职业等人本与行业字典 | **GB/T 2261.1/2261.2**（性别/婚姻）、**GB/T 4762**（政治面貌）、**GB/T 3304**（民族）、**GB/T 4658**（学历）、**GB/T 4754**（行业）、**GB/T 6565**（职业）、**GA/T 2000.156-2016**（证件类型主码）+ JR/T 0160-2018（金融别名） |
| `platform` | 平台标准 / 平台应用标准 | 待定义 |
| `sensitive` | 脱敏规则标识 `MaskRule`、声明接口 `Maskable`、执行 SPI `Masker`（仅定义接口与规则元数据，不含实现） | 自定 |

## 核心原则

### 1. 对齐优先级：国标 > ISO > 自定义

- 能与国标（GB 系列）对齐的与国标对齐；能与 ISO 对齐的与 ISO 对齐；都覆盖不到才自定义编码。
- 每个字典项的 Javadoc 必须写明依据的标准号（如 `GB/T 2261.1`）。
- 无国标但有权威行业标准的，主码取覆盖面最全的行业标准，其余作为别名兼容。例：证件类型无 GB 国标，主码取 GA/T 2000.156-2016（公安），内置 JR/T 0160-2018（金融 DM001）别名码。
- 同一标准在不同行业码值不同时，用**别名映射**兼容（枚举内置或 `AliasTable` SPI 外挂），不另立枚举。

### 2. 数据策略与容错：常用封闭枚举 + 冷门文件驱动 + UNKNOWN 兜底

- **小字典**（性别、民族、证件类型、货币等）：纯封闭枚举，编译期固化。
- **大数据集**（证照目录、行政区划市/县级）：常用项封闭枚举，冷门项由文件数据驱动——默认内置 classpath JSON，使用方可注册自定义目录文件。
- 查找统一经 Facade：`of(code)` 先查枚举、再查文件数据，对使用方无感知。
- **未知码值**：每个字典枚举必须含 `UNKNOWN` 项；严格查找（`of`）抛异常，宽容解析（`ofOrDefault`）与反序列化兜底一律落 `UNKNOWN`，不允许炸掉整条记录。
- **序列化约定（三层口径）**：DB 存 `code`；给前端的报文输出结构化 `CodeView{code, name, description}`（展示 `name`、回传 `code`，不断链）；回传兼容字符串/对象双形态，统一取 `code` 走宽容兜底。`UNKNOWN` 往返幂等；`CodeCodec` SPI 在核心，**Jackson 适配由 util4j 实现**，本体零依赖。

### 3. 职责边界

本库只**定义标准**：模型、接口、校验规则、掩码规则元数据。对应的执行实现（如脱敏算法）由使用方或专门的实现库按本库的 SPI 提供；框架集成（Spring 自动装配等）同样不在本库范围内。

## 构建要求

- 构建：Maven；groupId `com.asialjim`、artifactId `standard4j`、包前缀 `com.asialjim.standard4j`；**打包模式：单模块 jar（不使用 pom 聚合/父工程）**。
- **Java 基线：17（LTS）**——依据：`CodeView` 等 record（16+）、Jackson 3 在 util4j（要求 17+）、Spring Boot 3/Jakarta 生态基线；`release=17` 的产物可直接运行于 17/21/25。
- 纯模型 + 接口库，**不依赖 Spring 或任何运行时框架**（Lombok 为编译期 provided，不进传递依赖）。
